# KonkretnyTMS: main_dev (praca) i main (produkcja)

Cel: GitHub zawsze ma aktualny kod, także niesprawdzony testami, a deploy jest nadal jedynym miejscem, gdzie płaci się minutami CI.

| Gałąź | Kto pisze | Co uruchamia push |
|---|---|---|
| `main_dev` (domyślna na GitHubie) | kolejka po każdym issue, właściciel, laptop, chmura | nic, 0 minut CI |
| `main` | tylko release i hotfix | `Tests` → `Deploy` → webhook, jak dotąd |

Łańcuch deployu nie zmienia się w ogóle, bo `main` pozostaje produkcją.

## Przełączenie

Warunek: kolejka zatrzymana (`kolejka stop`, sesja tmux zamknięta), brak issue w toku.

```bash
S=~/Programowanie/claude-config/docs/plans/2026-11-07-main-dev-przelaczenie.sh
bash "$S" --sprawdz      # niczego nie zmienia
bash "$S" --wykonaj      # zatrzymuje się na pierwszym błędzie
```

Skrypt kolejno: scala toolkit 1.8.0 do master i publikuje go (push, marketplace, plugin), ustawia tag `przed-main-dev`, tworzy `main_dev`, scala `origin/main` i `agent/main-dev`, pushuje `main_dev`, cofa lokalny `main` na `origin/main`, ustawia gałąź domyślną, dopisuje `KOLEJKA_MAIN` i `KOLEJKA_WYPYCHAJ` do `~/.zshrc`, sprawdza, że nic się nie uruchomiło.

Po skrypcie: `source ~/.zshrc && kolejka start`.

## Release

Kolejka musi stać tylko na czas commitu wydania, bo preflight działa na jego SHA.

```bash
kolejka stop                                   # poczekaj na koniec issue
git log origin/main..main_dev --merges --grep '\[roadmapa\]'   # co wchodzi
# commit wydania wg CLAUDE.md §DEPLOY (bump, changelog, dist) na main_dev
scripts/ci-preflight.sh                        # gałąź ci/preflight/<sha12>, pełne testy
git push origin main_dev
git push origin <SHA>:main                     # fast-forward: Tests widzi zielony preflight, Deploy rusza
kolejka start                                  # można też zaraz po pushu main_dev; preflight dotyczy SHA, nie gałęzi
```

Musi to być fast-forward. `git merge --no-ff main_dev` na `main` daje nowy SHA, więc drugi pełny przebieg testów (ok. 66 minut jobów).

## Hotfix

Gałąź z `origin/main`, preflight, `git push origin <SHA>:main`. Watcher scali `origin/main` do `main_dev` przed następnym issue.

## Laptop i chmura

- Laptop: `git switch main_dev && git pull`. `dist/` na `main_dev` pochodzi z ostatniego wydania, więc lokalnie `USE_BUNDLE=false` w `index.php`.
- `claude --cloud` z laptopa klonuje bieżącą gałąź z GitHuba, więc lokalne commity trzeba najpierw wypchnąć (dokumentacja: claude-code-on-the-web). Dokumentacja nie opisuje wyboru gałęzi przy starcie z przeglądarki: sprawdzić przy pierwszej sesji. Gałąź domyślna `main_dev` pokrywa wariant bez wyboru.
- Praca wypchnięta do `main_dev` z innego komputera wchodzi do drzewa głównego przed następnym issue. Konflikt zatrzymuje kolejkę z listą plików; po ręcznym scaleniu `kolejka start`.

## Co się zmienia poza gałęziami

- `security-audit.yml` i `ksef-api-upstream.yml` (`schedule`) czytają teraz gałąź domyślną: audyt widzi kod z `main_dev`, czyli świeższy niż produkcja. Bez zmian w plikach.
- `sync-claude-toolkit.yml` zapisuje do gałęzi domyślnej, czyli do `main_dev`, a watcher to pobiera.
- `schedule-silence.yml` chodzi przy pushu do `main`, więc częstotliwość detekcji spada do częstotliwości wydań.
- `deploy.yml` i `znacznik-deployu.yml` działają z wersji na `main_dev`, zanim trafią na `main`. Dlatego bramka kolejki odmawia ich zmiany (`tylko-wlasciciel:` w `docs/VERIFICATION_ENV.md`).
- `bash-guard` czyta źródło refspecu: przed zmianą lokalny `main` równy `origin/main` przepuściłby release 100 nieprzejrzanych scaleń.
- `main` nie ma ochrony gałęzi (prywatne repo, plan darmowy). Pilnują go `.githooks/pre-push`, `bash-guard` i reguły.

## Wycofanie

Toolkit 1.8.0 bez `KOLEJKA_WYPYCHAJ` działa jak 1.7.9, więc nie wymaga cofania.

```bash
kolejka stop
gh repo edit --default-branch main
git switch main_dev && git branch -f main main_dev && git switch main   # praca z main_dev zostaje
git push origin --delete main_dev
# usuń z ~/.zshrc: KOLEJKA_MAIN, KOLEJKA_WYPYCHAJ
```

Tylko przed krokiem 3 skryptu (bez pusha): `git switch main && git branch -D main_dev && git tag -d przed-main-dev`.
